# Energy and sampled token evidence (0.8.0)

Engineering questions: what whole-system energy does the runtime observe, and where does sampled DeepSeek decode time go? The source-reviewed contract is Cachalot 0.64.17 (`cf328cc8cef9da37c4348054ddb0c4128e09c570`), briefs through 0.64.0. Source review is not live inference validation.

Cockpit Runtime presents collapsed energy and trace tables. Fields come from the current healthy snapshot, never from a saved launch setting or inferred model family. Missing, malformed, negative, unsafe or nonfinite values are unavailable; valid zero remains zero. Energy source availability is independent, unavailable reasons are retained, and runtime-defined stale samples are suppressed. Sample age is age at the poll. The meter's `since` is the retained ring start, while joules remain cumulative since creation. No rate is derived across ring rollover or restart.

System energy integrates whole-system SMC PSTR at the reported interval; it includes other apps, display and idle. Request energy excludes queue time. Decode is the last decode_seconds of that request and may be unavailable independently. Up to one sample interval of uncertainty at each end matters especially for short/first requests; the meter interpolates and extrapolates at most two intervals. IOReport components are SoC estimates, not a complete additive system breakdown, even though their raw runtime tag is measured. Frozen/unavailable counters stay unavailable. Lab never invokes sudo or starts powermetrics. SSD and DRAM-transport estimates are not added.

Trace means cover positionally sampled decode since server start and are drained after requests; no per-request trace attribution exists. Router eval includes queued GPU work, not a pure synchronization tax. Main-thread expert wait is exposed I/O, not a proven critical path or guaranteed faster-drive saving. Read busy is a union; time outside waits can overlap other activity. Boundary-crossing reads are omitted, so the runtime-derived exposed ratio is approximate, not token latency fraction. Missing loss metadata means completeness unverified; positive drops mean incomplete evidence. Means remain unavailable before any valid positive sampled count. No synthetic timeline is manufactured.

Dive Instrumentation offers nullable enablement and interval controls. Energy works across families on 0.63+; tracing requires an explicit DeepSeek family and 0.64+. Null choices emit no environment override and inherited keys are stripped; runtime defaults remain off. Lab interval bounds are 0.1–60 seconds and 1–65536 decode tokens, narrower than runtime parsing. Changing family clears trace choices and preserves all-family energy choices. Preview exposes the compiled settings, which apply only on next launch and do not establish active server state.

Collection uses the existing visible 1 Hz/hidden 0.2 Hz stats poll, no added endpoint or native sampler. Current raw stats are not persisted or exported. Raw request energy stays in the existing bounded conversation usage and reopens with that conversation; see [privacy](../PRIVACY.md). There is no new history, event export, run comparison or baseline subtraction.

Runtime 0.63.1 fixes component tail extrapolation; 0.63.2 verifies it but does not establish meter overhead. Continuous tracing measured +0.55 ms/token (95% +0.05 to +1.11), not certified against the 1 ms rule. Runtime 0.64.9 measures one-in-four average +0.274 ms/token (95% −0.065 to +0.645), not certified under the 0.5 ms upper-bound rule; this replaces the brief's derived 0.14 ms estimate. Runtime 0.64.8 withdraws router-sync-bound interpretation. 0.64.13 changes raw GET_END kept-expert payload without changing stats; later benchmark conclusions do not authorize policy changes. Lab rendering, transport and inference overhead remain unmeasured.

Regression coverage includes optional/old/partial/offline/stale/invalid data, independent unavailable components, zero, missing decode windows, no-sample means, loss, profile compatibility/validation, final SSE usage and saved chat energy. `python3 mock-runtime/server.py --port 18081 --observability --read-stats` exposes labeled synthetic fixtures for native inspection; these are not hardware measurements. Live model quality/performance, GPU timelines and matched overhead certification remain outstanding.
