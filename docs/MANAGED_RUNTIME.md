# Managed runtime groundwork

Studio 0.3.0 adds Cachalot 0.46+'s optional `CACHALOT_LOOP_GUARD_INCREMENTING` override for GLM and MiniMax. Empty inherits the runtime default of 64 list items; `0` disables it. Studio accepts 0 or 2–4096 and passes only validated values to its owned process. The `[loop guard] reply stopped after` log prefix now covers both repeated blocks and invented counting lists; Logs displays the raw line. Studio does not turn either text line into a per-request Cockpit warning.

New MiniMax profiles prefill default temperature 0.7, matching the 0.47 `serve-minimax.sh` script. Studio launches `python -m cachalot.cli serve` directly; an empty field still inherits that CLI's 0.6 default. Existing profiles retain their explicit value or empty inheritance. This distinction was checked against Cachalot 0.47.0 commit `77c99a009cddd85891235e16a4f5154625b35923` on 2026-09-30.

The native backend now stores versioned launch profiles in `profiles.json` under Studio's app data directory. Files use private permissions and atomic replacement; a file lock prevents two Studio instances from overwriting each other's updates. Up to 50 profiles are supported. Dive exposes the profile commands in Studio 0.2.0.

A profile contains a UUID, display name, absolute Python interpreter path, absolute model directory, local port (1024–65535), model family (`auto`, `deepseek`, `glm`, or `minimax`), and optional expert budget, maximum sequence length, I/O worker count, served model ID, default maximum output tokens, default temperature, and absolute prefix-snapshot directory. Omitted fields inherit the installed runtime's CLI defaults; old profile files remain readable. A snapshot directory lets the runtime reuse saved system blocks across managed restarts. API keys are not stored in profiles or inherited from Studio's `CACHALOT_API_KEY` environment variable. The compiler builds an argument vector for `python -m cachalot.cli serve`; it fixes the host to `127.0.0.1` and never invokes a shell.

Profiles also have optional runtime tuning overrides: MiniMax decode and prefill miss substitution, GLM/MiniMax loop-guard repeats, MiniMax decode buffer-cache size, MiniMax persisted-block retention, Cachalot 0.44+ host-memory quiet and shrink intervals, and Cachalot 0.45+ mirror-share adaptation. Omitted values inherit the installed runtime's defaults: 60 seconds before cache growth after host pressure, at most one pressure-driven slab return per 10 seconds, and adaptive mirror share on when a mirror is configured. A quiet interval of `0` disables the new watcher and restores the earlier governor. Studio validates explicit intervals from 0 through 3600 seconds; the 0.44+ controls have no effect on older runtimes. Explicit `false` for mirror adaptation writes `CACHALOT_MINIMAX_MIRROR_ADAPT=0`, keeping the configured fraction fixed on runtime 0.45.0 and later. Explicit `false` for either miss-substitution control writes `0` for that drop knob, which selects the exact path on runtime 0.43.0 and later; explicit `true` writes `0.20` and shared substitution depth `4`. Dive's "Exact outputs" preset sets both controls to `false`. Studio clears inherited copies of these controlled environment keys before launching a managed process, then passes only the profile's validated overrides. Old profile documents remain valid because the tuning object is optional.

MiniMax profiles can name an absolute expert bank directory and an optional matching mirror bank directory. Studio checks that each contains `bank.json` before launch and can set the mirror read fraction from 0 to 0.9. A mirror path requires a bank path; a fraction requires a mirror path. The runtime's own default fraction is 0.10 when omitted. These paths let Studio launch checkpoints whose routed experts live outside the model directory. The selected Python interpreter must have Cachalot installed; Studio does not install it.

Dive warns that enabling or disabling miss substitution changes model output and switches the disk-snapshot numerics tag. Cachalot 0.44.0 gives each runtime identity its own snapshot filename, so a saved system block can be reused after restart; switching configurations still requires each identity to create its own snapshot once. A trustworthy live mode indicator remains pending. An externally started server does not report its active numerics mode to Studio. Cachalot 0.45.0 emits `[bank] mirror share A -> B (configured C)` at most once a minute when adaptation moves the share by 0.03 or more. The Logs screen shows the raw line; Cockpit does not yet extract a mirror-share metric from it.

Studio's supervisor starts at most one profile process. It checks that the interpreter and model directory exist and that the chosen port can be bound before launch. It holds the child handle, reports its PID and exit status, and stops only that child. Normal stop sends SIGTERM, then force-stops after five seconds. Tauri's exit event stops the child during normal app shutdown. Output goes to a private `managed-runtime.log` file in app data. Studio does not attach to or stop an independently launched server.

The owner-approved [static Abyss and Surface mockups](../design/mockups/managed-runtime.html) remain a design reference. The Dive screen supports profile creation, editing, deletion, argument preview, start, and stop. Startup status probes `/health` and `/v1/models` every two seconds with a two-second request timeout. Once the owned child reports ready, Studio connects without replacing the saved external endpoint. It connects once per process; a manual later connection remains user-controlled. Studio disconnects that endpoint if the child exits. Doctor reports managed startup state. Logs and Dive show the latest 64 KiB of private `managed-runtime.log`, which is reset on each launch. They display raw lines, including the 0.43.2 cut-reply event, without interpreting them as structured warnings.

An abrupt app kill cannot run shutdown cleanup. Recovery is deliberately manual: after restart, Studio owns no prior child, never automatically attaches to or kills it, and refuses a new launch on an occupied port. The user must stop the old Cachalot server in Activity Monitor or choose a different port, then start a new Studio-owned process. This avoids terminating an unrelated process if a PID or port has been reused. Native Dive has been visually reviewed in the installed local build. On 2026-09-29, the installed local build launched MiniMax 0.45.1 with an external coded bank and mirror, reached readiness, auto-connected, streamed a two-token reply, and stopped the owned process cleanly. This local test verified launch behavior, not sustained performance.

CLI flags were checked against Cachalot runtime 0.45.3 commit `9147c2d30ef25f64be4597bea1b018be16d71608` (`src/cachalot/cli.py`) on 2026-09-29; that source file did not change after 0.45.1. New environment defaults and overrides were checked against 0.45.0 commit `cda463d`. Recheck flags and installed-runtime version before shipping a managed-runtime release.
