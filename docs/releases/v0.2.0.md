# Cachalot Studio 0.2.0

This minor release adds backward-compatible local runtime management, saved conversations, and a denser Cockpit to the 0.1.0 loopback client.

## Requirements

- Apple Silicon Mac running macOS 14 or newer.
- A separately installed Cachalot Python environment and model checkpoint. Studio does not install Python, Cachalot, model weights, or an updater.
- Managed MiniMax checkpoints with routed experts outside the model directory need their coded expert bank path in the Dive profile. An optional matching mirror bank can be configured.

## New in 0.2.0

- Dive stores local launch profiles, previews fixed CLI arguments, starts and stops one Studio-owned Cachalot process, waits for health and model readiness, and connects automatically. Profiles expose optional served model ID, generation defaults, snapshot directory, and versioned MiniMax tuning controls.
- Cockpit shows two-minute traces for reported model metrics and whole-Mac CPU, GPU, and memory. Missing runtime or driver data stays unavailable. macOS supplies matching machine artwork when available.
- Chat saves conversations locally and reopens them after restart. Chats stay bound to their original endpoint and model.
- API provides copy-ready curl, Python OpenAI SDK, and JavaScript OpenAI SDK examples. Doctor shows managed status; Logs displays the latest 64 KiB of private managed process output.
- A compact telemetry strip remains visible on screens outside Cockpit while connected. Runtime polling slows while the window is hidden.

## Compatibility and limits

- Studio connects only to loopback HTTP endpoints. API keys remain in memory and are never placed in copied examples or launch profiles.
- Cachalot 0.45.3 is the reviewed source baseline. Native managed startup and a short streamed reply were verified with MiniMax 0.45.1. Other model families and sustained workloads were not validated in that smoke test.
- An external Cachalot server does not report its active numerics mode to Studio. Cockpit labels it unreported rather than inferring it from model name or speed.
- Studio stops only its owned child. After an abrupt app exit, an occupied port blocks a new launch; stop the earlier process yourself or choose another port. Studio does not attach to or terminate an unknown process.
- No Keychain credential storage, model discovery, or automatic updates yet.
