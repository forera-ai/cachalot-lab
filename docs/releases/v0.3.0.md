# Cachalot Studio 0.3.0

This backward-compatible minor release saves generation controls with each chat and syncs managed launch controls with Cachalot 0.46–0.47.

## Requirements

- Apple Silicon Mac running macOS 14 or newer.
- A separately installed Cachalot Python environment and model checkpoint for managed runtimes. Studio does not install Python, Cachalot, model weights, or an updater.

## New in 0.3.0

- Chat saves Thinking, maximum output tokens, and optional temperature separately for each conversation. New chats start with the prior 2048-token and Thinking-off defaults. Existing saved chats still open. Leaving temperature empty lets the connected server choose its own default.
- Dive exposes Cachalot 0.46's incrementing-list loop guard for GLM and MiniMax managed profiles. Empty inherits the runtime default of 64 items; 0 disables it. Logs shows the raw guard line.
- New MiniMax profiles start with a 0.7 default temperature, matching the Cachalot 0.47 MiniMax launch script. Existing managed profiles keep their saved value or the direct CLI's 0.6 default when empty.
- The 0.2.1 host-memory fix, managed runtime controls, saved conversations, Cockpit, API examples, Doctor, and Logs remain included.

## Compatibility and limits

- Cachalot 0.47.0 commit `77c99a009cddd85891235e16a4f5154625b35923` is the reviewed source baseline. The last native managed MiniMax model smoke test used 0.45.1; this release's 0.46–0.47 changes were verified against source and tests, not a live 0.47.0 model launch.
- Studio connects only to loopback HTTP endpoints. API keys stay in memory and are not saved in conversations or launch profiles.
- The runtime does not expose active numerics mode or structured loop-guard events in `/v1/stats`. Cockpit does not infer either from logs or performance.
- After an abrupt app exit, Studio does not attach to or terminate a prior server. An occupied port blocks a new launch until it is cleared or a different port is selected.
