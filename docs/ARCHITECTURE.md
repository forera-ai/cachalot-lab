# Architecture

The Tauri Rust core owns local HTTP access. It accepts only loopback `http://` endpoints, holds the optional API key in memory, fetches health/models/stats, and streams chat over Server-Sent Events into window events. React never opens the runtime socket directly. Connection state and the active generation live in the Rust process. Cancellation aborts only the request started by Studio.

`src/runtime.ts` wraps native commands, auto-connects to the last local endpoint, and schedules non-overlapping stats polls once per second while visible or once per five seconds while hidden. It keeps a rolling two-minute in-memory history of reported model metrics, clearing it when the endpoint changes. `src/host.ts` samples whole-Mac CPU, GPU, and memory every two seconds while Cockpit is visible; `src-tauri/src/host.rs` reads Mach CPU and memory counters and the GPU driver's optional utilization value. `platform_info` reads macOS hardware details once. Host graphs must not be described as per-model utilization; missing runtime or driver fields remain unavailable, with no fabricated curves. `src/Cockpit.tsx` renders the dashboard; the compact telemetry strip remains visible on other screens. `src/RuntimeScreens.tsx` renders connection setup and the API example. `src/ChatScreen.tsx` renders chat and remains mounted while users navigate. The Rust module `src-tauri/src/conversations.rs` stores versioned conversations in Studio's app data directory with size limits, private file permissions, and atomic replacement. The UI queues saves during streaming and can reopen or delete chats. A saved chat is bound to its endpoint and model before it can be continued. `src/App.tsx` renders Doctor, Settings, and navigation. `src/store.ts` persists screen and theme preferences; local WebView storage also keeps the last endpoint. API keys are not persisted.

`design/tokens.json` is compiled by `scripts/generate-tokens.mjs` into CSS variables and TypeScript. The owner-selected mark in `assets/logo/` supplies app and theme assets. `mock-runtime/server.py` is a local test double, never bundled into the native app.

`platform_info` resolves the detected model identifier through macOS CoreTypes device declarations, follows icon inheritance, and converts the matching system `.icns` to a small PNG data URL for Cockpit. This uses the icon installed on the host Mac; Studio does not bundle Apple device artwork. A generic monitor glyph appears when macOS has no matching icon or conversion fails.

Native profile storage, a fixed-argument CLI compiler, validated environment overrides, and single-child process ownership back the Dive screen. Optional served-model ID, generation defaults, and snapshot directory compile to fixed CLI arguments; older profile files use runtime defaults. `src/managed.ts` polls managed status, connects once when the owned process reports healthy with a model ID, and leaves the saved external endpoint unchanged. `src/ManagedScreens.tsx` handles profile editing, launch preview, and bounded local log display. Doctor reads the same managed status. Rust reads only the latest 64 KiB of `managed-runtime.log`; each launch truncates that file. The versioned knobs and runtime log patterns checked through Cachalot 0.45.3 live in `runtime-contract/`; see [runtime compatibility](RUNTIME_SYNC.md) and [managed runtime](MANAGED_RUNTIME.md). The frontend never composes a shell command. Filesystem discovery, Keychain credentials, updates, and explicit recovery of an orphan after abrupt app termination remain later work.
