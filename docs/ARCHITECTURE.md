# Architecture

The governing mission is [Cachalot Lab's product direction](PRODUCT_DIRECTION.md).
The implementation described below is the existing foundation. Extend it incrementally:
Cachalot produces authoritative runtime evidence; native adapters validate and collect
it; Lab derives documented summaries and presents layered investigations. Do not move
inference policy into the UI. Future versioned run artifacts, bounded trace collection,
and comparison surfaces require explicit contracts and overhead evidence before shipping;
they are not implemented by this direction change. [Proposed observability requirements](../runtime-contract/observability-proposal.md)
remain separate from supported YAML contracts. See [rename compatibility](RENAME.md)
for the unchanged bundle, persistence, and Keychain identities.

The Tauri Rust core owns local HTTP access. It accepts only loopback `http://` endpoints, holds the optional API key in memory, fetches health/models/stats, and streams chat over Server-Sent Events into window events. React never opens the runtime socket directly. Connection state and the active generation live in the Rust process. Cancellation aborts only the request started by Lab.

`src/runtime.ts` wraps native commands, auto-connects to the last local endpoint, and schedules non-overlapping stats polls once per second while visible or once per five seconds while hidden. It keeps a rolling two-minute in-memory history of reported model metrics, clearing it when the endpoint changes. `src/host.ts` samples whole-Mac CPU, GPU, and memory every two seconds while Cockpit is visible; `src-tauri/src/host.rs` reads Mach CPU and memory counters and the GPU driver's optional utilization value. `platform_info` reads macOS hardware details once. Host graphs must not be described as per-model utilization; missing runtime or driver fields remain unavailable, with no fabricated curves. `src/Cockpit.tsx` renders the dashboard and optional image input and prefetch read/used totals directly from the current healthy snapshot. Totals accept only nonnegative safe integers, clear offline, and remain unavailable when omitted; no rate or performance benefit is inferred. Image inputs may count video steps, resent history and incomplete requests; they are not capability discovery. The compact telemetry strip remains visible on other screens. `src/RuntimeScreens.tsx` renders connection setup and the API example. `src/ChatScreen.tsx` renders chat and remains mounted while users navigate. The Rust module `src-tauri/src/conversations.rs` stores versioned conversations in Lab's app data directory with size limits, private file permissions, and atomic replacement. The UI queues saves during streaming and can reopen or delete chats. A saved chat is bound to its endpoint and model before it can be continued. `src/App.tsx` renders Doctor, Settings, and navigation. `src/store.ts` persists screen, theme, and silent-running preferences; local WebView storage also keeps the last endpoint. Keys remain session-only unless explicitly saved in macOS Keychain; they are never persisted in WebView storage.

`design/tokens.json` is compiled by `scripts/generate-tokens.mjs` into CSS variables and TypeScript. The owner-selected mark in `assets/logo/` supplies app and theme assets. `mock-runtime/server.py` is a local test double, never bundled into the native app.

`platform_info` resolves the detected model identifier through macOS CoreTypes device declarations, follows icon inheritance, and converts the matching system `.icns` to a small PNG data URL for Cockpit. This uses the icon installed on the host Mac; Lab does not bundle Apple device artwork. A generic monitor glyph appears when macOS has no matching icon or conversion fails.

Chat generation settings are stored with each conversation as an optional field in the existing versioned file. Older conversations receive the UI's previous defaults. The Rust chat command validates output length and optional temperature, then includes temperature in the HTTP request only when set; an empty field leaves the server default in control.

Native profile storage, a fixed-argument CLI compiler, validated environment overrides, and single-child process ownership back the Dive screen. Optional served-model ID, generation defaults, and snapshot directory compile to fixed CLI arguments; older profile files use runtime defaults. Nullable family-specific tuning preserves explicit zero and false values. Lab 0.4.0 adds GLM bank and prefetch controls: Rust rejects overrides for other families and removes inherited controlled keys before applying the compiled environment. Enabled banks require a manifest before launch; the runtime validates its format and layer files. `src/managed.ts` polls managed status, connects once when the owned process reports healthy with a model ID, and leaves the saved external endpoint unchanged. `src/ManagedScreens.tsx` handles profile editing, launch preview, and bounded local log display. Doctor reads the same managed status. Rust reads only the latest 64 KiB of `managed-runtime.log`; each launch truncates that file. The versioned knobs, optional telemetry fields, and runtime log patterns checked through Cachalot 0.61.2 live in `runtime-contract/`; see [runtime compatibility](RUNTIME_SYNC.md) and [managed runtime](MANAGED_RUNTIME.md). The frontend never composes a shell command. Lab 0.5.0 adds bounded filesystem discovery and optional Keychain credentials; updates and explicit recovery of an orphan after abrupt app termination remain later work.

Silent running defaults to Off and persists in the existing WebView preference store. Each Cockpit trace returns a paused placeholder instead of a live SVG while enabled; data collection continues, so disabling it restores the current two-minute history. The document preference disables CSS transitions and animations, and the command palette also selects zero-duration Motion transitions. System reduced motion remains honored independently. It does not change process ownership, window-close behavior, network polling, or generation settings.

DeepSeek runtime tuning (Lab 0.4.0) uses two nullable profile fields for decode miss dropping and system-date reuse. Rust enforces DeepSeek family ownership and compiles explicit budget 0/-1 and reuse 1/0 into the managed child environment. The supervisor removes inherited budget, date switch, and date-window keys before applying profile overrides. No profile migration changes older defaults; Dive clears tuning on family changes. These are launch intentions, not inferred live mode. Direct CLI and `serve.sh` defaults remain distinguished in UI and runtime contracts.

The current local SSD slice extends the host sample with optional physical-drive counters. Rust parses the IOKit property-list output for `IOBlockStorageDriver`, accepts one whole media child per driver, and excludes partition entries and incomplete counter records. Counter values cross the JavaScript bridge as decimal strings to preserve u64 precision. The frontend uses BigInt subtraction and elapsed monotonic time to derive decimal MB/s, matched by driver registry ID and BSD name. First observations, reset counters, malformed counters, and gaps longer than 15 seconds have no rate. Sampling failures clear host history and the baseline. Drive disappearance leaves the selected device unavailable rather than silently attributing another drive's activity to it. Native whole-drive activity remains separate from runtime `ssd_gbps`; neither implies SSD pressure or benchmark capacity.

Local discovery uses `src-tauri/src/discovery.rs` and `src/ModelDiscovery.tsx`. A blocking metadata scan checks the chosen root and three descendant levels, with limits of 1,000 directories, 10,000 traversed entries, 64 models, and 2 MiB per config. Hidden/known dependency directories and descendant directory symlinks are skipped. Recognized model directories are terminal scan nodes. Invalid configurations and unreadable directories are counted; reaching a limit is explicit. Weight-file presence checks are capped at 10,000 entries and do not establish checkpoint completeness. Discovery never changes profiles until the user saves the draft.

`src-tauri/src/credentials.rs` provides optional macOS Keychain storage through Security.framework generic passwords, with normalized loopback origins as account names. Commands expose presence/save/delete, never the saved secret. `connect_runtime` loads a saved key only when requested; an explicit typed key wins. Startup reconnection requests Keychain, while managed runtime auto-connection does not. Credential failures report redacted OS status, and runtime HTTP redirects are disabled. Non-macOS builds report Keychain unavailable.

Dive styling is scoped to the managed page in `src/styles.css`: consistent 40-pixel controls, wrapping action rows, destructive state tokens in both themes, contained paths, and responsive card/form/discovery layouts. Preview results are labeled as executable/arguments/environment, bounded within the details card, dismissible, and discarded when their asynchronous request no longer matches the current selection. Profile deletion requires a separate inline confirmation and remains disabled for the owned profile. Stop is offered only for the selected owned runtime; another active profile blocks Start. Compact runtime output uses a native details disclosure while Logs remains independently available.

## Runtime read/wait evidence (0.6.0)

Cockpit's Runtime view validates nine optional counts/bytes/durations independently
from the current healthy snapshot and presents them in a collapsed, bounded-scroll
table. Opening it replaces the panel's traces; closing restores them. Existing
prefetch totals accept GLM/MiniMax 0.61.1 exports. No new polling, persistence,
policy, or derived latency/rate is added. See the versioned telemetry contract for
reset lifetime, heuristic cache labels, unknown emulation state, and older-runtime
fallback. The Lab rename preserves bundle, preference, and Keychain identities.
